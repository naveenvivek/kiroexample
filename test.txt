The Business Model
There are three ways to deliver reusable AI blocks:
1. Platform Model (Backbase, Temenos approach) — You build a platform with a library of blocks. Banks subscribe and configure. Highest revenue, hardest to build.
2. Accelerator Model (Neurons Lab approach) — Pre-built blocks that consultants deploy and customize at each bank. Faster to market, services-heavy.
3. Open Core Model — Open-source the block framework, sell enterprise features (governance, compliance, support). Good for adoption, harder to monetize.

MCP vs Traditional API: Why MCP Wins for Banking AI Blocks
The core difference is this: an API exposes fixed endpoints that return data. An MCP server exposes tools, resources, and context that AI agents can reason with. This is a fundamental shift.
Traditional API Approach

Bank's System → calls POST /api/convert → gets back converted file


The bank writes custom integration code for every block. Each block needs its own API client, error handling, and retry logic. If you add a new block, the bank needs new integration code.
MCP Approach

Bank's AI Agent → discovers MCP server → sees available tools → reasons about which to use → calls them


The bank’s AI agent (Claude, GPT, LangGraph, etc.) automatically discovers what your blocks can do, understands the context, and chains them together intelligently — without custom integration code.
The 7 Benefits of MCP for Banking AI Blocks
1. Universal Discovery — Banks Don’t Need Custom Integration Code
MCP provides a unified, plug-and-play interface that significantly reduces integration complexity, eliminating the need for custom API development ￼. Your banking blocks would be automatically discoverable by any MCP-compatible client. Think of MCP as “USB-C for AI applications” — a universal connector that allows any AI model to communicate with any tool through a single, standardized interface ￼.
With traditional APIs, if you build 3 blocks (format converter, report generator, document classifier), each bank needs to write 3 separate API integrations. With MCP, the bank connects once and their AI agent sees all 3 tools instantly.
2. AI Agents Can Chain Blocks Autonomously
This is the killer benefit. With MCP, a bank’s AI agent can reason about your blocks and chain them together without any human programming:

MCP operates on a client-server architecture with three core primitives: Resources (structured data sources), Tools (executable functions), and Prompts (reusable templates) ￼. Your blocks would be exposed as Tools that any bank’s agent can invoke.
3. Context Sharing Across Blocks
With APIs, each call is isolated — the format converter doesn’t know what the sanctions screener found. With MCP, the protocol provides context that transforms disconnected experiments into an enterprise nervous system — if the fraud detection system flagged a suspicious wire transfer, the customer onboarding system that already verified this customer’s information can share that context ￼.
For your blocks this means: the format converter can pass enriched metadata (detected format, confidence score, corrected fields) directly to the reporting block through shared MCP context — no manual plumbing needed.
4. Enterprise-Grade Security Built Into the Protocol
MCP’s March 2025 security update introduced comprehensive OAuth 2.1 support with mandatory PKCE, enabling enterprise-grade authentication through existing identity providers like Okta and Microsoft Entra ID ￼. This aligns with PSD2/PSD3 strong authentication, BSA/AML requirements, and EU DORA cybersecurity requirements.
Banks don’t need to build their own authentication layer — MCP handles identity verification, granular permissions, and audit trails natively.
5. Industry Momentum Is Massive
MCP server downloads grew from approximately 100,000 in November 2024 to over 8 million by April 2025, with over 5,800 MCP servers and 300+ MCP clients now available, and major deployments at Block, Bloomberg, and Amazon ￼. The protocol was donated to the Linux Foundation’s newly formed Agentic AI Foundation in December 2025, ensuring vendor-neutral governance ￼.
The MCP market is expected to reach $1.8B in 2025, driven by strong demand from highly regulated fields like healthcare, finance, and manufacturing — and 2026 marks the transition from experimentation to enterprise-wide adoption ￼.
This means your blocks would be compatible with what every bank is already adopting.
6. Works With Any LLM — Model Agnostic
Banks use different LLMs (BNP uses Mistral, Goldman uses GPT+Claude+Gemini, Nomura uses LLaMA). MCP is model-agnostic — it standardizes how applications provide context to large language models, creating a universal bridge connecting AI models with tools, databases, and external APIs ￼. Your blocks work regardless of which LLM the bank chooses.
7. Regulatory Compliance by Design
MCP ensures uniformity in data access formats, reduced risk from translation or interpretation errors, and easier auditing and monitoring through clear exchange rules — especially critical in fintech environments where accuracy, security, and regulatory compliance are priorities ￼.
Every tool call through MCP is logged, authenticated, and auditable — exactly what DORA and the EU AI Act require.

Privacy: MCP Doesn’t Change the Hosting Model
This is critical — MCP is a protocol, not a hosting decision. Your MCP servers still deploy exactly the same way as before:
	∙	On-premise: MCP server runs as a Docker container inside the bank’s data centre
	∙	Hybrid: MCP server distributed via CAGIP to 39 regional banks
	∙	The bank’s data never leaves their infrastructure
	∙	MCP just defines HOW the bank’s agent talks to your block, not WHERE
The privacy model is identical to the hybrid approach we discussed earlier. MCP actually enhances privacy because it has built-in access controls and audit trails at the protocol level.
